# 从 v6 升级

<docs-info>

React Router v7 要求以下最低版本：

- `node@20`
- `react@18`
- `react-dom@18`

</docs-info>

如果你已经启用了所有 future flag，v7 升级将不会有任何破坏性变更。这些 flag 允许你逐步更新应用，每次处理一个变更。我们强烈建议你在每一步完成后提交代码并部署，而不是一次性完成所有更改。

## 更新到最新的 v6.x

首先更新到 v6.x 的最新小版本，以获取最新的 future flag 和控制台警告。

👉 **更新到最新的 v6**

```shellscript nonumber
npm install react-router-dom@6
```

### v7_relativeSplatPath

**背景**

更改了多段通配符路径（如 `dashboard/*`，而非仅 `*`）的相对路径匹配和链接行为。[查看 CHANGELOG](https://github.com/remix-run/react-router/blob/main/CHANGELOG.md#futurev7_relativesplatpath) 了解更多信息。

👉 **启用该 flag**

启用 flag 的方式取决于路由器类型：

```tsx
<BrowserRouter
  future={{
    v7_relativeSplatPath: true,
  }}
/>
```

```tsx
createBrowserRouter(routes, {
  future: {
    v7_relativeSplatPath: true,
  },
});
```

**更新你的代码**

如果你有类似 `<Route path="dashboard/*">` 的路由，且其下有相对链接如 `<Link to="relative">` 或 `<Link to="../relative">`，你需要更新代码。

👉 **将 `<Route>` 拆分为两个**

将所有多段通配符 `<Route>` 拆分为一个带路径的父路由和一个带通配符的子路由：

```diff
<Routes>
  <Route path="/" element={<Home />} />
-  <Route path="dashboard/*" element={<Dashboard />} />
+  <Route path="dashboard">
+    <Route path="*" element={<Dashboard />} />
+  </Route>
</Routes>

// 或
createBrowserRouter([
  { path: "/", element: <Home /> },
  {
-    path: "dashboard/*",
-    element: <Dashboard />,
+    path: "dashboard",
+    children: [{ path: "*", element: <Dashboard /> }],
  },
]);
```

👉 **更新相对链接**

更新该路由树中所有的 `<Link>` 元素，添加额外的 `..` 相对路径段，以继续链接到相同的位置：

```diff
function Dashboard() {
  return (
    <div>
      <h2>Dashboard</h2>
      <nav>
         <Link to="/">Dashboard Home</Link>
-        <Link to="team">Team</Link>
-        <Link to="projects">Projects</Link>
+        <Link to="../team">Team</Link>
+        <Link to="../projects">Projects</Link>
      </nav>

      <Routes>
        <Route path="/" element={<DashboardHome />} />
        <Route path="team" element={<DashboardTeam />} />
        <Route
          path="projects"
          element={<DashboardProjects />}
        />
      </Routes>
    </div>
  );
}
```

### v7_startTransition

**背景**

此 flag 将路由状态更新从 `React.useState` 切换为 `React.useTransition`。查看 [CHANGELOG](https://github.com/remix-run/react-router/blob/main/CHANGELOG.md#futurev7_starttransition) 了解更多信息。

👉 **启用该 flag**

```tsx
<BrowserRouter
  future={{
    v7_startTransition: true,
  }}
/>

// 或
<RouterProvider
  future={{
    v7_startTransition: true,
  }}
/>
```

👉 **更新你的代码**

除非你在组件*内部*使用了 `React.lazy`，否则不需要更新任何内容。

在组件内部使用 `React.lazy` 与 `React.useTransition`（或其他在组件内部创建 Promise 的代码）不兼容。将 `React.lazy` 移到模块作用域，并停止在组件内部创建 Promise。这不是 React Router 的限制，而是 React 的不正确用法。

### v7_fetcherPersist

<docs-warning>如果你没有使用 `<RouterProvider>`，可以跳过此步骤</docs-warning>

**背景**

fetcher 的生命周期现在基于其返回空闲状态的时间，而不是其所属组件卸载的时间。[查看 CHANGELOG](https://github.com/remix-run/react-router/blob/main/CHANGELOG.md#persistence-future-flag-futurev7_fetcherpersist) 了解更多信息。

**启用该 Flag**

```tsx
createBrowserRouter(routes, {
  future: {
    v7_fetcherPersist: true,
  },
});
```

**更新你的代码**

这不太可能影响你的应用。你可能需要检查 `useFetchers` 的使用，因为 fetcher 可能比以前存在更长的时间。根据你的具体操作，你可能会渲染某些内容更长的时间。

### v7_normalizeFormMethod

<docs-warning>如果你没有使用 `<RouterProvider>`，可以跳过此步骤</docs-warning>

此 flag 将 `formMethod` 字段规范化为大写的 HTTP 方法，与 `fetch()` 的行为保持一致。[查看 CHANGELOG](https://github.com/remix-run/react-router/blob/main/CHANGELOG.md#futurev7_normalizeformmethod) 了解更多信息。

👉 **启用该 Flag**

```tsx
createBrowserRouter(routes, {
  future: {
    v7_normalizeFormMethod: true,
  },
});
```

**更新你的代码**

如果你的代码中检查了小写的 HTTP 方法，你需要将其更新为大写（或对其调用 `toLowerCase()`）。

👉 **将 `formMethod` 与大写进行比较**

```diff
-useNavigation().formMethod === "post"
-useFetcher().formMethod === "get";
+useNavigation().formMethod === "POST"
+useFetcher().formMethod === "GET";
```

### v7_partialHydration

<docs-warning>如果你没有使用 `<RouterProvider>`，可以跳过此步骤</docs-warning>

此 flag 启用数据路由的部分注水，主要用于 SSR 框架，但如果你使用 `lazy` 加载路由模块也很有用。你不太可能需要担心这个，只需开启该 flag 即可。[查看 CHANGELOG](https://github.com/remix-run/react-router/blob/main/CHANGELOG.md#partial-hydration) 了解更多信息。

👉 **启用该 Flag**

```tsx
createBrowserRouter(routes, {
  future: {
    v7_partialHydration: true,
  },
});
```

**更新你的代码**

启用部分注水后，你需要提供一个 `HydrateFallback` 组件在初始注水期间渲染。此外，如果你之前使用了 `fallbackElement`，需要将其移除，因为它已被废弃。在大多数情况下，你可以将 `fallbackElement` 复用为 `HydrateFallback`。

👉 **将 `fallbackElement` 替换为 `HydrateFallback`**

```diff
const router = createBrowserRouter(
  [
    {
      path: "/",
      Component: Layout,
+      HydrateFallback: Fallback,
      // 或
+      hydrateFallbackElement: <Fallback />,
      children: [],
    },
  ],
);


<RouterProvider
  router={router}
-  fallbackElement={<Fallback />}
/>
```

### v7_skipActionErrorRevalidation

<docs-warning>如果你没有使用 `createBrowserRouter`，可以跳过此步骤</docs-warning>

启用此 flag 后，在 action 抛出错误或返回 `4xx`/`5xx` 状态码的 `Response` 后，loader 将不再默认重新验证。你可以通过 `shouldRevalidate` 和 `actionStatus` 参数在这些场景中手动启用重新验证。

👉 **启用该 Flag**

```tsx
createBrowserRouter(routes, {
  future: {
    v7_skipActionErrorRevalidation: true,
  },
});
```

**更新你的代码**

大多数情况下，你可能不需要修改应用代码。通常，如果 action 出错，数据不太可能被修改，因此不需要重新验证。如果你的代码确实在 action 错误场景中修改了数据，你有两个选择：

👉 **选项 1：修改 `action` 以避免在错误场景中进行数据变更**

```js
// 之前
async function action() {
  await mutateSomeData();
  if (detectError()) {
    throw new Response(error, { status: 400 });
  }
  await mutateOtherData();
  // ...
}

// 之后
async function action() {
  if (detectError()) {
    throw new Response(error, { status: 400 });
  }
  // 所有数据变更现在都在验证之后执行
  await mutateSomeData();
  await mutateOtherData();
  // ...
}
```

👉 **选项 2：通过 `shouldRevalidate` 和 `actionStatus` 手动启用重新验证**

```js
async function action() {
  await mutateSomeData();
  if (detectError()) {
    throw new Response(error, { status: 400 });
  }
  await mutateOtherData();
}

async function loader() { ... }

function shouldRevalidate({ actionStatus, defaultShouldRevalidate }) {
  if (actionStatus != null && actionStatus >= 400) {
    // 当 action 返回 4xx/5xx 状态码时重新验证此 loader
    return true;
  }
  return defaultShouldRevalidate;
}
```

## 废弃项

`json` 和 `defer` 方法已被废弃，建议直接返回原始对象。

```diff
async function loader() {
- return json({ data });
+ return { data };
```

如果你之前使用 `json` 将数据序列化为 JSON，可以改用原生的 [Response.json()][response-json] 方法。

## 升级到 v7

现在你的应用已经跟上了所有变更，理论上可以无痛升级到 v7。

👉 **安装 v7**

```shellscript nonumber
npm install react-router-dom@latest
```

👉 **将 react-router-dom 替换为 react-router**

在 v7 中我们不再需要 `"react-router-dom"`，因为包已经简化。你可以从 `"react-router"` 导入所有内容：

```shellscript nonumber
npm uninstall react-router-dom
npm install react-router@latest
```

注意：你的 package.json 中只需要 `"react-router"`。

👉 **更新导入**

现在你应该将导入更新为使用 `react-router`：

```diff
-import { useLocation } from "react-router-dom";
+import { useLocation } from "react-router";
```

你也可以使用以下命令自动更新导入，而非手动修改。不过请确保你的 git 工作区是干净的，以便在结果不符合预期时可以回退。

```shellscript nonumber
find ./path/to/src \( -name "*.tsx" -o -name "*.ts" -o -name "*.js" -o -name "*.jsx" \) -type f -exec sed -i '' 's|from "react-router-dom"|from "react-router"|g' {} +
```

如果你安装了 GNU `sed`（大多数 Linux 发行版），请使用以下命令：

```shellscript nonumber
find ./path/to/src \( -name "*.tsx" -o -name "*.ts" -o -name "*.js" -o -name "*.jsx" \) -type f -exec sed -i 's|from "react-router-dom"|from "react-router"|g' {} +
```

👉 **更新 DOM 特定的导入**

`RouterProvider` 和 `HydratedRouter` 需要从深层导入路径引入，因为它们依赖 `"react-dom"`：

```diff
-import { RouterProvider } from "react-router-dom";
+import { RouterProvider } from "react-router/dom";
```

注意：在非 DOM 环境（如 Jest 测试）中，你应该使用顶层导入：

```diff
-import { RouterProvider } from "react-router-dom";
+import { RouterProvider } from "react-router";
```

恭喜，你现在已经升级到 v7 了！
