# 从 v5 升级

## 向后兼容包

与其一次性升级和更新所有代码（这非常困难且容易出错），向后兼容包允许你通过同时运行 v5 和 v6，一次升级一个组件、一个 hook 和一个路由。任何你没有触碰的代码仍然运行之前完全相同的代码。一旦所有组件都完全使用 v6 API，你的应用就不再需要兼容包，并且完全运行在 v6 上。官方指南可以在[这里](https://github.com/remix-run/react-router/discussions/8753)找到。

如果你的应用有超过几个路由，我们建议使用向后兼容包来升级。否则，我们希望本指南能帮助你一次性完成升级！

## 介绍

React Router 版本 6 引入了几个强大的新功能，以及与最新版本 React 的改进兼容性。它还从版本 5 引入了一些破坏性更改。本文档是将 v4/5 应用升级到 v6 的全面指南，希望你在升级过程中能尽可能频繁地发布。

本指南中的示例将展示你可能在 v5 应用中构建某些东西的代码示例，然后是你如何在 v6 中实现相同的东西。还会解释我们为什么进行这个更改，以及它将如何改善你的代码和使用你应用的人的整体用户体验。

总体来说，过程如下：

1. [升级到 React v16.8 或更高版本](#upgrade-to-react-v168)
2. [升级到 React Router v5.1](#upgrade-to-react-router-v51)
   - [移除 `<Switch>` 内的 `<Redirect>`](#remove-redirects-inside-switch)
   - [重构自定义 `<Route>`](#refactor-custom-routes)
3. [升级到 React Router v6](#upgrade-to-react-router-v6)

以下是每个步骤的详细说明，应该能帮助你快速、自信地迁移到 v6。

## 升级到 React v16.8

React Router v6 大量使用 [React hooks](https://reactjs.org/docs/hooks-intro.html)，因此你需要先升级到 React 16.8 或更高版本，然后再尝试升级到 React Router v6。好消息是 React Router v5 兼容 React >= 15，所以如果你在 v5（或 v4）上，应该可以升级 React 而不需要触碰任何路由代码。

升级到 React 16.8 后，**你应该部署你的应用**。然后你可以之后再回来继续。

## 升级到 React Router v5.1

如果你先升级到 v5.1，切换到 React Router v6 会更容易。在 v5.1 中，我们发布了对 `<Route children>` 元素处理的增强，这将有助于平滑过渡到 v6。不再使用 `<Route component>` 和 `<Route render>` props，而是到处使用常规元素 `<Route children>` 并用 hooks 访问路由器内部状态。

```js
// v4 and v5 before 5.1
function User({ id }) {
  // ...
}

function App() {
  return (
    <Switch>
      <Route exact path="/" component={Home} />
      <Route path="/about" component={About} />
      <Route
        path="/users/:id"
        render={({ match }) => (
          <User id={match.params.id} />
        )}
      />
    </Switch>
  );
}

// v5.1 preferred style
function User() {
  let { id } = useParams();
  // ...
}

function App() {
  return (
    <Switch>
      <Route exact path="/">
        <Home />
      </Route>
      <Route path="/about">
        <About />
      </Route>
      {/* 也可以使用命名的 `children` prop */}
      <Route path="/users/:id" children={<User />} />
    </Switch>
  );
}
```

You can read more about v5.1's hooks API and the rationale behind the move to regular elements [on our blog](https://reacttraining.com/blog/react-router-v5-1/).

In general, React Router v5.1 (and v6) favors elements over components (or "element types"). There are a few reasons for this, but we'll discuss more further down when we discuss v6's `<Route>` API.

When you use regular React elements you get to pass the props explicitly. This helps with code readability and maintenance over time. If you were using `<Route render>` to get a hold of the params, you can just
`useParams` inside your route component instead.

Along with the upgrade to v5.1, you should replace any usage of `withRouter` with hooks. You should also get rid of any "floating" `<Route>` elements that are not inside a `<Switch>`. Again, [the blog post about v5.1](https://reacttraining.com/blog/react-router-v5-1/) explains how to do this in greater detail.

In summary, to upgrade from v4/5 to v5.1, you should:

- Use `<Route children>` instead of `<Route render>` and/or `<Route component>`
  props
- Use [our hooks API](https://reacttraining.com/react-router/web/api/Hooks) to
  access router state like the current location and params
- Replace all uses of `withRouter` with hooks
- Replace any `<Route>`s that are not inside a `<Switch>` with `useRouteMatch`,
  or wrap them in a `<Switch>`

### Remove `<Redirect>`s inside `<Switch>`

Remove any `<Redirect>` elements that are directly inside a `<Switch>`.

If you want to redirect on the initial render, you should move the redirect logic to your server (we [wrote more about this here](https://gist.github.com/mjackson/b5748add2795ce7448a366ae8f8ae3bb)).

If you want to redirect client-side, move your `<Redirect>` into a `<Route render>` prop.

```tsx
// Change this:
<Switch>
  <Redirect from="about" to="about-us" />
</Switch>

// to this:
<Switch>
  <Route path="about" render={() => <Redirect to="about-us" />} />
</Switch>
```

Normal `<Redirect>` elements that are not inside a `<Switch>` are ok to remain. They will become `<Navigate>` elements in v6.

### Refactor custom `<Route>`s

Replace any elements inside a `<Switch>` that are not plain `<Route>` elements with a regular `<Route>`. This includes any `<PrivateRoute>`-style custom components.

You can [read more about the rationale behind this here](https://gist.github.com/mjackson/d54b40a094277b7afdd6b81f51a0393f), including some tips about how to use a `<Route render>` prop in v5 to achieve the same effect.

### Ship it!

Again, **once your app is upgraded to v5.1 you should test and deploy it**, and pick this guide back up when you're ready to continue.

## Upgrade to React Router v6

**Heads up:** This is the biggest step in the migration and will probably take the most time and effort.

For this step, you'll need to install React Router v6. If you're managing dependencies via npm:

```bash
$ npm install react-router-dom
# or, for a React Native app
$ npm install react-router-native
```

You'll also want to remove the `history` dependency from your package.json. The `history` library is a direct dependency of v6 (not a peer dep), so you won't ever import or use it directly. Instead, you'll use the `useNavigate()` hook for all navigation (see below).

### Upgrade all `<Switch>` elements to `<Routes>`

React Router v6 introduces a `Routes` component that is kind of like `Switch`, but a lot more powerful. The main advantages of `Routes` over `Switch` are:

- All `<Route>`s and `<Link>`s inside a `<Routes>` are relative. This leads to
  leaner and more predictable code in `<Route path>` and `<Link to>`
- Routes are chosen based on the best match instead of being traversed in order.
  This avoids bugs due to unreachable routes because they were defined later
  in your `<Switch>`
- Routes may be nested in one place instead of being spread out in different
  components. In small to medium-sized apps, this lets you easily see all your
  routes at once. In large apps, you can still nest routes in bundles that you
  load dynamically via `React.lazy`

In order to use v6, you'll need to convert all your `<Switch>` elements to `<Routes>`. If you already made the upgrade to v5.1, you're halfway there.

First, let's talk about relative routes and links in v6.

### Relative Routes and Links

In v5, you had to be very explicit about how you wanted to nest your routes and links. In both cases, if you wanted nested routes and links you had to build the `<Route path>` and `<Link to>` props from the parent route's `match.url` and `match.path` properties. Additionally, if you wanted to nest routes, you had to put them in the child route's component.

```js
// This is a React Router v5 app
import {
  BrowserRouter,
  Switch,
  Route,
  Link,
  useRouteMatch,
} from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <Switch>
        <Route exact path="/">
          <Home />
        </Route>
        <Route path="/users">
          <Users />
        </Route>
      </Switch>
    </BrowserRouter>
  );
}

function Users() {
  // 在 v5 中，嵌套路由由子组件渲染，所以
  // 你的应用中到处都有 <Switch> 元素用于嵌套 UI。
  // 你使用 match.url 和 match.path 构建嵌套路由和链接。
  let match = useRouteMatch();

  return (
    <div>
      <nav>
        <Link to={`${match.url}/me`}>My Profile</Link>
      </nav>

      <Switch>
        <Route path={`${match.path}/me`}>
          <OwnUserProfile />
        </Route>
        <Route path={`${match.path}/:id`}>
          <UserProfile />
        </Route>
      </Switch>
    </div>
  );
}
```

这是同一个应用在 v6 中的写法：

```js
// This is a React Router v6 app
import {
  BrowserRouter,
  Routes,
  Route,
  Link,
} from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="users/*" element={<Users />} />
      </Routes>
    </BrowserRouter>
  );
}

function Users() {
  return (
    <div>
      <nav>
        <Link to="me">My Profile</Link>
      </nav>

      <Routes>
        <Route path=":id" element={<UserProfile />} />
        <Route path="me" element={<OwnUserProfile />} />
      </Routes>
    </div>
  );
}
```

在此示例中，v6 的几个重要变化值得注意：

- `<Route path>` 和 `<Link to>` 是相对的。这意味着它们会自动基于父路由的 path 和 URL 构建，所以你不必手动插值 `match.url` 或 `match.path`
- `<Route exact>` 已移除。相反，带有后代路由（在其他组件中定义）的路由在其路径中使用尾部 `*` 来表示深度匹配
- 你可以按任意顺序放置路由，路由器将自动检测当前 URL 的最佳路由。这防止了因为在 `<Switch>` 中手动将路由放在错误顺序而导致的 bug

你可能还注意到，v5 应用中所有的 `<Route children>` 在 v6 中变成了 `<Route element>`。假设你已经按照 v5.1 的升级步骤进行，这应该只是将你的路由元素从子位置移到命名的 `element` prop 那么简单。

### `<Route element>` 的优势

在关于升级到 v5.1 的部分，我们承诺会讨论使用常规元素而不是组件（或元素类型）进行渲染的优势。让我们从升级中暂停一下，现在来谈谈这个。

首先，我们看到 React 本身在这方面引领潮流，通过 `<Suspense fallback={<Spinner />}>` API。`fallback` prop 接受一个 React 元素，而不是组件。这让你可以轻松地从渲染它的组件传递任意 props 到 `<Spinner>`。

使用元素而不是组件意味着我们不必提供 `passProps` 风格的 API 来将所需 props 传递到元素。例如，在基于组件的 API 中，没有好的方法将 props 传递给 `<Route path=":userId" component={Profile} />` 匹配时渲染的 `<Profile>` 元素。大多数采用这种方式的 React 库最终会有类似 `<Route component={Profile} passProps={{ animate: true }} />` 的 API，或者使用 render prop 或高阶组件。

另外，如果你没注意到，在 v4 和 v5 中 `Route` 的渲染 API 变得相当庞大。它大致是这样的：

```js
// 啊，这很简洁明了！
<Route path=":userId" component={Profile} />

// 但等等，我如何向 <Profile> 元素传递自定义 props？？
// 嗯，也许我们可以在这些情况下使用 render prop？
<Route
  path=":userId"
  render={routeProps => (
    <Profile routeProps={routeProps} animate={true} />
  )}
/>

// 好吧，现在我们有两种方式来用路由渲染东西。:/

// 但等等，如果我们想在路由不匹配 URL 时渲染某些东西，
// 比如 Not Found 页面呢？也许我们可以用另一个
// 语义略有不同的 render prop？
<Route
  path=":userId"
  children={({ match }) => (
    match ? (
      <Profile match={match} animate={true} />
    ) : (
      <NotFound />
    )
  )}
/>

// 如果我想访问路由匹配，或者我需要
// 在树的更深处重定向呢？
function DeepComponent(routeStuff) {
  // 拿到了 routeStuff，松口气！
}
export default withRouter(DeepComponent);

// 好吧，至少我们现在覆盖了所有用例！
// ... *捂脸*
```

API 膨胀的至少部分原因是 React 没有提供任何方法让我们将 `<Route>` 的信息传递给你的路由元素，所以我们不得不发明巧妙的方法来同时传递路由数据**和**你自己的自定义 props 到你的元素：`component`、render props、`passProps` 高阶组件... 直到 **hooks** 出现！

现在，上面的对话变成了这样：

```js
// 啊，简洁明了的 API。而且跟 <Suspense> API 一样！
// 这里没有什么额外要学的。
<Route path=":userId" element={<Profile />} />

// 但等等，我如何向 <Profile>
// 元素传递自定义 props？哦对，它只是一个元素。简单。
<Route path=":userId" element={<Profile animate={true} />} />

// 好吧，但我如何访问路由器的数据，比如 URL 参数
// 或当前 location？
function Profile({ animate }) {
  let params = useParams();
  let location = useLocation();
}

// 那树深处的组件呢？
function DeepComponent() {
  // 哦对，和其他地方一样
  let navigate = useNavigate();
}

// 好的的的的的，我们到此结束。
```

使用 `element` prop 的另一个重要原因是 `<Route children>` 被保留用于嵌套路由。这是 v3 和 `@reach/router` 中人们最喜欢的功能之一，我们将其带回 v6。将前面示例的代码再进一步，我们可以将所有 `<Route>` 元素提升到单个路由配置中：

```js
// This is a React Router v6 app
import {
  BrowserRouter,
  Routes,
  Route,
  Link,
  Outlet,
} from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="users" element={<Users />}>
          <Route path="me" element={<OwnUserProfile />} />
          <Route path=":id" element={<UserProfile />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}

function Users() {
  return (
    <div>
      <nav>
        <Link to="me">My Profile</Link>
      </nav>

      <Outlet />
    </div>
  );
}
```

这个步骤当然是可选的，但对于没有数千个路由的中小型应用来说非常不错。

注意 `<Route>` 元素如何自然地嵌套在 `<Routes>` 元素内。嵌套路由通过添加到父路由路径来构建其路径。这次我们不需要在 `<Route path="users">` 上添加尾部 `*`，因为当路由定义在一个地方时，路由器能看到你所有的嵌套路由。

只有当该路由的后代树中某处有另一个 `<Routes>` 时，你才需要尾部 `*`。在这种情况下，后代 `<Routes>` 将匹配 pathname 的剩余部分（查看前面的示例了解实际效果）。

当使用嵌套配置时，带有 `children` 的路由应该渲染一个 `<Outlet>` 来渲染其子路由。这使得使用嵌套 UI 渲染布局变得容易。

### 关于 `<Route path>` 模式的说明

React Router v6 使用简化的路径格式。v6 中的 `<Route path>` 只支持 2 种占位符：动态 `:id` 样式的参数和 `*` 通配符。`*` 通配符只能用在路径末尾，不能在中间。

以下所有都是 v6 中有效的路由路径：

```
/groups
/groups/admin
/users/:id
/users/:id/messages
/files/*
/files/:id/*
```

以下正则表达式样式的路由路径在 v6 中**无效**：

```
/users/:id?
/tweets/:id(\d+)
/files/*/cat.jpg
/files-*
```

我们在 v4 中添加了 path-to-regexp 依赖以启用更高级的模式匹配。在 v6 中，我们使用更简单的语法，允许我们可预测地解析路径以进行排名。这也意味着我们可以停止依赖 path-to-regexp，这对 bundle 大小很友好。

如果你使用了 path-to-regexp 的任何高级语法，你需要移除它并简化你的路由路径。如果你使用正则表达式语法做 URL 参数验证（例如确保 id 全是数字字符），请知道我们计划在 v6 中某个时候添加更高级的参数验证。目前，你需要将该逻辑移到路由渲染的组件中，在解析参数后让它分支其渲染树。

如果你使用了 `<Route sensitive>`，你应该将它移到包含它的 `<Routes caseSensitive>` prop。`<Routes>` 元素中的所有路由要么都区分大小写，要么都不区分。

另一个需要注意的是，v6 中的所有路径匹配都忽略 URL 上的尾部斜杠。实际上，`<Route strict>` 已被移除，在 v6 中没有效果。**这并不意味着你不能使用尾部斜杠。** 你的应用可以决定是否使用尾部斜杠，你只是不能在客户端在 `<Route path="edit">` 和 `<Route path="edit/">` 上渲染两个不同的 UI。你仍然可以在这些 URL 上渲染两个不同的 UI（尽管我们不建议），但你必须在服务器端完成。

### 关于 `<Link to>` 值的说明

在 v5 中，不以 `/` 开头的 `<Link to>` 值是模糊的；它取决于当前 URL 是什么。例如，如果当前 URL 是 `/users`，v5 的 `<Link to="me">` 会渲染一个 `<a href="/me">`。但是，如果当前 URL 有尾部斜杠，比如 `/users/`，同样的 `<Link to="me">` 会渲染 `<a href="/users/me">`。这使得链接行为难以预测，所以在 v5 中我们建议你从根 URL（使用 `match.url`）构建链接，不使用相对的 `<Link to>` 值。

React Router v6 修复了这个模糊性。在 v6 中，`<Link to="me">` 无论当前 URL 如何，始终渲染相同的 `<a href>`。

例如，在 `<Route path="users">` 内渲染的 `<Link to="me">` 始终会渲染一个指向 `/users/me` 的链接，无论当前 URL 是否有尾部斜杠。

当你想链接“向上”到父路由时，在 `<Link to>` 值中使用前导 `..` 路径段，类似于你在 `<a href>` 中所做的。

```tsx
function App() {
  return (
    <Routes>
      <Route path="users" element={<Users />}>
        <Route path=":id" element={<UserProfile />} />
      </Route>
    </Routes>
  );
}

function Users() {
  return (
    <div>
      <h2>
        {/* 这链接到 /users - 当前路由 */}
        <Link to=".">Users</Link>
      </h2>

      <ul>
        {users.map((user) => (
          <li>
            {/* 这链接到 /users/:id - 子路由 */}
            <Link to={user.id}>{user.name}</Link>
          </li>
        ))}
      </ul>
    </div>
  );
}

function UserProfile() {
  return (
    <div>
      <h2>
        {/* 这链接到 /users - 父路由 */}
        <Link to="..">All Users</Link>
      </h2>

      <h2>
        {/* 这链接到 /users/:id - 当前路由 */}
        <Link to=".">User Profile</Link>
      </h2>

      <h2>
        {/* 这链接到 /users/mj - 一个“兄弟”路由 */}
        <Link to="../mj">MJ</Link>
      </h2>
    </div>
  );
}
```

可以把当前 URL 想象成文件系统上的目录路径，`<Link to>` 就像 `cd` 命令行工具。

```
// If your routes look like this
<Route path="app">
  <Route path="dashboard">
    <Route path="stats" />
  </Route>
</Route>

// 当前 URL 是 /app/dashboard（有或没有
// 尾部斜杠）
<Link to="stats">               => <a href="/app/dashboard/stats">
<Link to="../stats">            => <a href="/app/stats">
<Link to="../../stats">         => <a href="/stats">
<Link to="../../../stats">      => <a href="/stats">

// 在命令行上，如果当前目录是 /app/dashboard
cd stats                        # pwd is /app/dashboard/stats
cd ../stats                     # pwd is /app/stats
cd ../../stats                  # pwd is /stats
cd ../../../stats               # pwd is /stats
```

**注意**：我们团队在匹配和创建相对路径时忽略尾部斜杠的决定并非轻率做出的。我们咨询了许多朋友和客户（他们也是我们的朋友！）。我们发现我们大多数人甚至不理解纯 HTML 相对链接如何处理尾部斜杠。大多数人猜测它像命令行的 `cd`（实际上并不是）。此外，HTML 相对链接没有嵌套路由的概念，它们只在 URL 上工作，所以我们必须在这里开辟自己的道路。`@reach/router` 设定了这个先例，它已经运行了好几年效果很好。

除了忽略当前 URL 中的尾部斜杠外，还需要注意 `<Link to="..">` 并不总是像 `<a href="..">` 那样工作，当你的 `<Route path>` 匹配超过一个 URL 段时。不是只移除 URL 的一个段，**它会基于父路由的路径解析，本质上移除该路由指定的所有路径段**。

```tsx
function App() {
  return (
    <Routes>
      <Route path="users">
        <Route
          path=":id/messages"
          element={
            // 这链接到 /users
            <Link to=".." />
          }
        />
      </Route>
    </Routes>
  );
}
```

这看起来像是个奇怪的选择，让 `..` 基于路由而不是 URL 段操作，但在处理 `*` 路由时这是一个**巨大的**帮助，因为 `*` 可能匹配不确定数量的段。在这些场景中，`<Link to>` 值中的单个 `..` 段本质上可以移除 `*` 匹配的任何内容，这让你能在 `*` 路由中创建更可预测的链接。

```tsx
function App() {
  return (
    <Routes>
      <Route path=":userId">
        <Route path="messages" element={<UserMessages />} />
        <Route
          path="files/*"
          element={
            // 这链接到 /:userId/messages，无论
            // * 匹配了多少段
            <Link to="../messages" />
          }
        />
      </Route>
    </Routes>
  );
}
```

## 将 `<Link>` state 作为单独的 prop 传递

v6 中的 `Link` 组件接受 `state` 作为单独的 prop，而不是作为传递给 `to` 的对象的一部分，所以如果你的 `Link` 组件使用了 state，你需要更新它们：

```js
import { Link } from "react-router-dom";

// 将这个：
<Link to={{ pathname: "/home", state: state }} />

// 改为：
<Link to="/home" state={state} />
```

state 值仍然通过 `useLocation()` 在链接的组件中获取：

```js
function Home() {
  const location = useLocation();
  const state = location.state;
  return <div>Home</div>;
}
```

## 使用 `useRoutes` 代替 `react-router-config`

v5 的 `react-router-config` 包的所有功能都已移入 v6 核心。如果你喜欢/需要将路由定义为 JavaScript 对象而不是使用 React 元素，你会喜欢这个。

```js
function App() {
  let element = useRoutes([
    // 这些与你提供给 <Route> 的 props 相同
    { path: "/", element: <Home /> },
    { path: "dashboard", element: <Dashboard /> },
    {
      path: "invoices",
      element: <Invoices />,
      // 嵌套路由使用 children 属性，这也与
      // <Route> 相同
      children: [
        { path: ":id", element: <Invoice /> },
        { path: "sent", element: <SentInvoices /> },
      ],
    },
    // Not found 路由按预期工作
    { path: "*", element: <NotFound /> },
  ]);

  // 返回的元素将渲染整个元素
  // 层级结构，包含它需要的所有适当的 context
  return element;
}
```

以这种方式定义的路由遵循与 `<Routes>` 相同的所有语义。实际上，`<Routes>` 只是 `useRoutes` 的包装器。

我们鼓励你同时尝试 `<Routes>` 和 `useRoutes`，自己决定更喜欢用哪个。老实说，我们两个都喜欢并使用。

如果你之前自己实现了一些关于数据获取和服务端渲染的逻辑，我们还提供了一个低级的 `matchRoutes` 函数，类似于我们在 react-router-config 中提供的那个。

## 使用 `useNavigate` 代替 `useHistory`

React Router v6 引入了一个新的导航 API，与 `<Link>` 同义，并且与支持 suspense 的应用提供更好的兼容性。我们根据你的风格和需求提供了命令式和声明式两种版本的该 API。

```js
// 这是一个 React Router v5 应用
import { useHistory } from "react-router-dom";

function App() {
  let history = useHistory();
  function handleClick() {
    history.push("/home");
  }
  return (
    <div>
      <button onClick={handleClick}>go home</button>
    </div>
  );
}
```

在 v6 中，这个应用应该重写为使用 `navigate` API。大多数时候这意味着将 `useHistory` 改为 `useNavigate`，并更改 `history.push` 或 `history.replace` 的调用处。

```js
// 这是一个 React Router v6 应用
import { useNavigate } from "react-router-dom";

function App() {
  let navigate = useNavigate();
  function handleClick() {
    navigate("/home");
  }
  return (
    <div>
      <button onClick={handleClick}>go home</button>
    </div>
  );
}
```

如果你需要替换当前位置而不是将新位置推入历史栈，使用 `navigate(to, { replace: true })`。如果你需要 state，使用 `navigate(to, { state })`。你可以将 `navigate` 的第一个参数视为你的 `<Link to>`，其他参数视为 `replace` 和 `state` props。

如果你更喜欢使用声明式导航 API（类似 v5 的 `Redirect` 组件），v6 提供了一个 `Navigate` 组件。像这样使用：

```js
import { Navigate } from "react-router-dom";

function App() {
  return <Navigate to="/home" replace state={state} />;
}
```

**注意**：请注意 v5 的 `<Redirect />` 默认使用 `replace` 逻辑（你可以通过 `push` prop 更改），而 v6 的 `<Navigate />` 默认使用 `push` 逻辑，你可以通过 `replace` prop 更改。

```js
// 将这个：
<Redirect to="about" />
<Redirect to="home" push />

// 改为：
<Navigate to="about" replace />
<Navigate to="home" />
```

如果你当前使用 `useHistory` 的 `go`、`goBack` 或 `goForward` 进行前后导航，你也应该用带数字参数的 `navigate` 替换它们，表示在历史栈中移动指针的位置。例如，以下是使用 v5 的 `useHistory` hook 的一些代码：

```js
// 这是一个 React Router v5 应用
import { useHistory } from "react-router-dom";

function App() {
  const { go, goBack, goForward } = useHistory();

  return (
    <>
      <button onClick={() => go(-2)}>
        Go 2 pages back
      </button>
      <button onClick={goBack}>Go back</button>
      <button onClick={goForward}>Go forward</button>
      <button onClick={() => go(2)}>
        Go 2 pages forward
      </button>
    </>
  );
}
```

以下是 v6 的等价应用：

```js
// 这是一个 React Router v6 应用
import { useNavigate } from "react-router-dom";

function App() {
  const navigate = useNavigate();

  return (
    <>
      <button onClick={() => navigate(-2)}>
        Go 2 pages back
      </button>
      <button onClick={() => navigate(-1)}>Go back</button>
      <button onClick={() => navigate(1)}>
        Go forward
      </button>
      <button onClick={() => navigate(2)}>
        Go 2 pages forward
      </button>
    </>
  );
}
```

我们从直接使用 `history` API 转向 `navigate` API 的主要原因之一是为了提供与 React suspense 更好的兼容性。React Router v6 在组件层级的根部使用 `useNavigation` hook。这让我们在用户交互需要中断正在进行的路由导航时提供更平滑的体验，例如当他们在之前点击的链接仍在加载时点击了另一个路由的链接。`navigate` API 了解内部的待定导航状态，会执行 REPLACE 而不是 PUSH 到历史栈，这样用户就不会在历史中留下实际从未加载的页面。

_注意：v5 的 `<Redirect>` 元素不再作为路由配置的一部分被支持（在 `<Routes>` 内）。这是因为 React 即将发布的变更使得在初始渲染期间更改路由器状态变得不安全。如果你需要立即重定向，你可以 a) 在服务器上做（可能是最好的方案）或 b) 在路由组件中渲染一个 `<Navigate>` 元素。但请注意，导航将在 `useEffect` 中发生。_

除了 suspense 兼容性外，`navigate` 和 `Link` 一样支持相对导航。例如：

```jsx
// 假设我们在 `/stuff`
function SomeForm() {
  let navigate = useNavigate();
  return (
    <form
      onSubmit={async (event) => {
        let newRecord = await saveDataFromForm(
          event.target,
        );
        // 你可以自己构建 URL
        navigate(`/stuff/${newRecord.id}`);
        // 或者相对导航，就像 Link 一样
        navigate(`${newRecord.id}`);
      }}
    >
      {/* ... */}
    </form>
  );
}
```

## 移除 `<Link>` 的 `component` prop

`<Link>` 不再支持用于覆盖返回的锚标签的 `component` prop。这有几个原因。

首先，`<Link>` 基本上应该始终渲染一个 `<a>`。如果你的不是，那么你的应用很可能存在严重的无障碍性和可用性问题，这可不好。浏览器为我们提供了很多 `<a>` 的可用性特性，我们希望你的用户能免费获得这些！

话说回来，也许你的应用使用了 CSS-in-JS 库，或者你的设计系统中已经有了一个自定义的花哨链接组件，你想渲染它。`component` prop 在 hooks 出现之前的世界可能够用，但现在你可以只用我们的几个 hooks 就创建你自己的无障碍 `Link` 组件：

```tsx
import { FancyPantsLink } from "@fancy-pants/design-system";
import {
  useHref,
  useLinkClickHandler,
} from "react-router-dom";

const Link = React.forwardRef(
  (
    {
      onClick,
      replace = false,
      state,
      target,
      to,
      ...rest
    },
    ref,
  ) => {
    let href = useHref(to);
    let handleClick = useLinkClickHandler(to, {
      replace,
      state,
      target,
    });

    return (
      <FancyPantsLink
        {...rest}
        href={href}
        onClick={(event) => {
          onClick?.(event);
          if (!event.defaultPrevented) {
            handleClick(event);
          }
        }}
        ref={ref}
        target={target}
      />
    );
  },
);
```

如果你使用 `react-router-native`，我们提供了 `useLinkPressHandler`，工作方式基本相同。只需在 `Link` 的 `onPress` 处理程序中调用该 hook 返回的函数就可以了。

## 将 `<NavLink exact>` 重命名为 `<NavLink end>`

这是一个简单的 prop 重命名，以更好地与 React 生态系统中其他库的常见做法保持一致。

## 从 `<NavLink />` 移除 `activeClassName` 和 `activeStyle` props

从 `v6.0.0-beta.3` 起，`activeClassName` 和 `activeStyle` props 已从 `NavLinkProps` 中移除。取而代之，你可以向 `style` 或 `className` 传递一个函数，该函数允许你根据组件的活动状态自定义内联样式或类名字符串。

```diff tsx
<NavLink
  to="/messages"
- style={{ color: 'blue' }}
- activeStyle={{ color: 'green' }}
+ style={({ isActive }) => ({ color: isActive ? 'green' : 'blue' })}
>
  Messages
</NavLink>
```

```diff tsx
<NavLink
  to="/messages"
- className="nav-link"
- activeClassName="activated"
+ className={({ isActive }) => "nav-link" + (isActive ? " activated" : "")}
>
  Messages
</NavLink>
```

如果你喜欢保留 v5 的 props，你可以创建自己的 `<NavLink />` 作为包装组件，以实现更平滑的升级路径。

```tsx
import * as React from "react";
import { NavLink as BaseNavLink } from "react-router-dom";

const NavLink = React.forwardRef(
  ({ activeClassName, activeStyle, ...props }, ref) => {
    return (
      <BaseNavLink
        ref={ref}
        {...props}
        className={({ isActive }) =>
          [
            props.className,
            isActive ? activeClassName : null,
          ]
            .filter(Boolean)
            .join(" ")
        }
        style={({ isActive }) => ({
          ...props.style,
          ...(isActive ? activeStyle : null),
        })}
      />
    );
  },
);
```

## 从 `react-router-dom/server` 获取 `StaticRouter`

`StaticRouter` 组件已移到新的 bundle：`react-router-dom/server`。

```js
// 将这个
import { StaticRouter } from "react-router-dom";
// 改为
import { StaticRouter } from "react-router-dom/server";
```

此更改既是为了更紧密地遵循 `react-dom` 包建立的约定，也是为了帮助用户更好地理解 `<StaticRouter>` 的用途和何时应该使用它（在服务器上）。

## 用 `useMatch` 替换 `useRouteMatch`

`useMatch` 与 v5 的 `useRouteMatch` 非常相似，但有几个关键区别：

- 它使用我们新的[路径模式匹配算法](#note-on-route-path-patterns)
- 模式参数现在是必需的
- 不再接受模式数组
- 当传递模式为对象时，一些选项已重命名以更好地与 v6 中的其他 API 保持一致
  - `useRouteMatch({ strict })` 现在是 `useMatch({ end })`
  - `useRouteMatch({ sensitive })` 现在是 `useMatch({ caseSensitive })`
- 它返回一个不同结构的匹配对象

要查看新 `useMatch` hook 的确切 API 及其类型声明，请查看我们的 [API 参考](../hooks/use-match)。

## 更改传递给 `matchPath` 的参数顺序。更改 pathPattern 选项。

从版本 6 开始，传递给 `matchPath` 函数的参数顺序已更改。另外模式选项也已更改。

- 第一个参数是 pathPattern 对象，然后是 pathname
- pathPattern 不再包含 `exact` 和 `strict` 选项。新增了 `caseSensitive` 和 `end` 选项。

请按如下方式重构：

之前：

```js
// 这是一个 React Router v5 应用
import { matchPath } from "react-router-dom";

const match = matchPath("/users/123", {
  path: "/users/:id",
  exact: true, // 可选，默认为 false
  strict: false, // 可选，默认为 false
});
```

之后：

```js
// 这是一个 React Router v6 应用
import { matchPath } from "react-router-dom";

const match = matchPath(
  {
    path: "/users/:id",
    caseSensitive: false, // 可选，`true` == `path` 的静态部分应匹配大小写
    end: true, // 可选，`true` == 模式应匹配整个 URL pathname
  },
  "/users/123",
);
```

## `<Prompt>` 目前不受支持

v5 的 `<Prompt>`（以及 v6 beta 版中的 `usePrompt` 和 `useBlocker`）未包含在当前发布的 v6 版本中。我们决定宁可发布现有的功能，也不想花更多时间去完善一个还没有完全成熟的功能。我们绝对会在不久的将来将其添加回 v6，但不会在 6.x 的第一个稳定版本中。

<docs-info>我们后来添加了 [`useBlocker`][useblocker] 和 [`unstable_usePrompt`][useprompt] 的实现，你可以用它们代替 `<Prompt>`</docs-info>
